# FitTrack demo

The prepared local database is `fittrack_demo_showcase_4a68d92d`. It is separate from the normal application database. All people and records are fictional; payments remain simulated.

## Launch the prepared demo

Start local MongoDB. In a terminal opened in `FitTrack/backend`, run:

```powershell
node --env-file=.env.demo.local src/server.js
```

In a second terminal opened in `FitTrack/frontend`, run:

```powershell
npm run dev
```

Open the local URL printed by Vite. The backend uses port 5000, matching the frontend proxy. Stop any existing backend on that port first. Environment variables already set in the terminal take precedence over the env file; use a fresh terminal without MONGODB_URI/PORT overrides for these commands. The normal backend .env was not changed.

The password for all active demo accounts is the DEMO_PASSWORD value in `backend/.env.demo.local`. This file also contains a random demo JWT secret and the database selection. It is covered by the existing `.env.*` ignore rule. Keep it local; it is not a documentation/sample file for publishing.

## Dataset

Eight users (one admin, one trainer, six members), three membership plans (one inactive), six membership histories, six payments, three sessions (scheduled/completed/cancelled), eight attendance entries, five progress measurements, one exercise, one two-item weekly workout and one partially completed assignment.

Dates are relative to the first seed run in UTC. The main member's upcoming session is tomorrow at 10:00 UTC within trainer availability and membership coverage. Notifications are generated by the normal API from source records, not manually inserted. Session reminders appear only within 24 hours; other reminders age out naturally. Re-running preserves original dates and edits.

## Seed another demo

From `FitTrack/backend`:

```powershell
$env:DEMO_DB = 'fittrack_demo_practice'
$demoPassword = Read-Host 'Demo password (12+ characters, at most 72 UTF-8 bytes)' -AsSecureString
try {
  $env:DEMO_PASSWORD = [System.Net.NetworkCredential]::new('', $demoPassword).Password
  npm run seed:demo
} finally {
  Remove-Item Env:DEMO_PASSWORD -ErrorAction SilentlyContinue
  Remove-Item Env:DEMO_DB -ErrorAction SilentlyContinue
  Remove-Variable demoPassword
}
```

The seeder connects only to local MongoDB at 127.0.0.1:27017. It ignores MONGODB_URI and the application's .env. DEMO_DB defaults to fittrack_demo and only allows that name or lowercase alphanumeric underscore-separated suffixes. Passwords are bcrypt-hashed and never printed. To run the application against a new demo, explicitly set MONGODB_URI to its local database and provide a valid JWT_SECRET as described in README.md.

A completed seed rerun is a no-op: it preserves edits, passwords, dates and IDs and reports the original seed inventory. It refuses unknown nonempty databases. A fixed run marker prevents concurrent seeds; an interrupted/failed run stays marked and is not automatically resumed or erased. Choose a fresh suffix to recover or refresh dates. There is deliberately no reset/drop option.
